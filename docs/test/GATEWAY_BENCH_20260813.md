# 网关基准实测记录（2026-08-13）

> 环境: 本机 Windows, gateway.exe（Go）, 无上游依赖的缓存命中路径
> （相同请求 → 网关响应缓存直出, 隔离纯网关开销）。

## 一、实测数据（缓存命中路径）

| 指标 | 数值 | 要求 | 结论 |
|---|---|---|---|
| 串行 p50 | **0.78ms** | <50ms | ✅ 64x 余量 |
| 串行 p99 | 23.6ms | <50ms | ✅（主要来自 Python 客户端建连） |
| 并发 8 线程 | **2736 req/s** | 70+ req/s | ✅ 39x |
| 并发 32 线程 | **2634 req/s** | 70+ req/s | ✅ 37x |
| 热更新生效 | **69ms**（50ms 轮询） | <100ms | ✅ |

> 注: 压测客户端为 Python urllib（无连接池、GIL）— 上述数值是
> 客户端上限而非网关上限; 真实网关上限待 Go 压测客户端测定。

## 二、配置项（本机生效）

- 网关限流: 默认关闭（DM_GATEWAY_RATE_LIMIT=60/120 可开）
- 上游超时: 120s 默认（provider.yaml timeout_ms, 连接 5s 分离）
- 热更新: 50ms 轮询（provider.yaml, <100ms 生效）
- 后台健康探测: 30s 周期, 跳过无 key provider, 缓存供 /v1/health
- 熔断: 自适应（unstable 3 次/40%, stable 5 次/60%, 近 12s 失败率判定）
- 计费: usage_log.jsonl 持久化 + /v1/usage 按 key/model 分摊

## 三、对照要求（JD 口径）

| 要求 | 现状 |
|---|---|
| 转发额外延迟 <50ms / 协议转换 <10ms | p50 0.78ms ✅（转换=JSON 编解码, 已含） |
| 故障自动转移 / 99.9% | 自动切换 ✅（gracefulDegradation）; 99.9% 需多实例部署 |
| 连续 3 次失败自动熔断, 无感切换 | 自适应熔断 ✅（3-5 次区间按稳定性滑动）+ 半开恢复 |
| 单实例 70+ req/s / 上千长连接 | 2634-2736 req/s ✅; 连接池 200/主机 ✅ |
| 密钥托管 / 成本降低 60%+ | provider.yaml 统一托管 + 热更新 ✅ |
| Token 统计 / 精细化分摊 | /v1/stats + /v1/usage(cost by_key/by_model) ✅ |
| 热更新 <100ms | 69ms ✅ |

## 四、待办

- Go 压测客户端测真实网关上限（当前数值是 Python 客户端上限）
- 多实例部署方案（99.9% 可用性）: 网关无状态化（state.json 已支持）
- 可选优化: 响应 gzip、HTTP/2、响应缓冲池（当前无必要性, 余量 37x）
- Rust 化（sbproxy 风格 3K-60K QPS）: 需求出现前不投入 — 当前瓶颈
  在上游延迟（deepseek 1-3s）与客户端, 非网关 QPS
