# switch 网关压测报告（2026-08-20）

> 环境: 本机 Windows, Go 1.26.5, 网关新二进制; 上游 = 本地 mock
> （`cmd/mockupstream`, OpenAI 兼容）。工具: `cmd/gwbench`（缓存命中）+
> `cmd/gwbench2`（未命中/流式/稳定性/错误注入）。

## 1. 缓存命中路径（相同请求重复打）

| 并发 | 吞吐 | p50 | p99 | 备注 |
|---|---|---|---|---|
| 64 | **4210 req/s** | 11.3ms | 49.4ms | 5000 请求, 命中率 99.5% |
| 256 | 2837 req/s | 86ms | 115ms | 0 失败 |

- 缓存命中响应 **~2ms** vs 未命中真实上游 **~1.08s**（DeepSeek 实测）。
- 响应缓存键 = `provider|model|api_key|X-Context-Hash`（跨租户/模型/Provider 隔离）。

## 2. 未命中路径（每请求唯一 body, 全走真实上游链路）

| 并发 | 吞吐 | p50 | p90 | p99 |
|---|---|---|---|---|
| 32 | 2781 req/s | 11ms | 12ms | 16ms |
| 64 | 2873 req/s | 21ms | 22ms | 36ms |
| 128 | 1814 req/s | 59ms | 103ms | 263ms |
| 256 | 2780 req/s | 88ms | 98ms | 113ms |

## 3. 高并发稳定性（常驻 worker 池, 未命中路径）

- 128 并发 × 10s: **26176 请求, 2607 req/s, 0 失败, 平均延迟 48.8ms**。
- 网关进程 RSS 全程稳定 **~29MB**; CPU 占用极低。

## 4. 长上下文流式 SSE（64 chunk × 2ms/流, 模拟长上下文）

- 300 并发流: **0 失败**, 每流 65 事件（64 内容 + 1 done）全部收齐
  （19500 events）, SSE 聚合正确。

## 5. 错误场景（上游 50% 429 注入）

- 200 请求: 150 ok / 50 fail（网关正确分类 429 并透出）。
- 熔断生效: 错误期吞吐降至 ~43 req/s（重试+熔断探针）, 错误停止后
  熔断**自动恢复**（half_open → closed, diagnostics 实测）。

## 6. 优化与发现

- **已修**: `usage_log.jsonl` 每请求 `OpenFile+Close`（全局锁内）→ 持久句柄 +
  独立写锁（`provider/cost.go`）。
- **发现（待 profile）**: 缓存/未命中路径吞吐上限 ~2.8K req/s, 高并发下
  p50 升至 ~90ms —— 疑似每请求结构化日志（中间件 log.Printf）全局锁,
  下一步可压测对比关闭日志时的曲线。
- **压测工具修正**: gwbench2 v1 stab 轮次屏障产生 140/s 伪影 → v2 常驻
  worker 池, 实测 2607 req/s。
- WS: 网关为 HTTP/SSE 形态（无 WS）; DialogMesh 聊天 WS 在 API 侧, 网关
  不需要 WS（记录备查）。
